# House Price Predictor — Linear Regression Full-Stack ML App

A complete, runnable full-stack Machine Learning web application: a Linear
Regression model trained on housing data, served through a **FastAPI** REST
API, with a **plain HTML/CSS/JavaScript** frontend that calls the API and
displays predictions live, with no page reloads.

---

## 1. Objective

Demonstrate the full Machine Learning application lifecycle end-to-end:

`Dataset → Cleaning → Training → Evaluation → Saved Model → REST API → Web UI → Live Prediction`

Given a **house size in square feet**, the trained model predicts the
**estimated house price**.

---

## 2. Features

- Real, documented dataset with a clear, explainable single-feature
  relationship (see Section 4).
- Full preprocessing pipeline: type checking, missing-value handling,
  duplicate removal.
- Linear Regression model trained with scikit-learn.
- Model evaluation with R², MAE, MSE, and RMSE.
- Model persistence with Joblib (train once, reuse instantly for predictions).
- FastAPI backend with input validation (Pydantic), CORS, error handling, and
  automatic interactive API docs (Swagger UI at `/docs`).
- Responsive, modern frontend with a prediction card, live model performance
  table, dataset info panel, loading indicator, and error handling.
- No frontend framework — pure HTML5, CSS3, and vanilla JavaScript (`fetch`).

## 4. Dataset

**File:** `dataset/data.csv` (generated by `dataset/generate_dataset.py`)

**Where it comes from:**
Live real-estate pricing APIs (Zillow, Realtor.com, MLS feeds, etc.) all
require paid API keys and registration, which makes them unsuitable for a
project that needs to run immediately, offline, with zero configuration.
Instead, `generate_dataset.py` **generates a realistic dataset from real,
published market statistics** — a typical US price-per-square-foot range
(~$148/sq. ft.), a realistic fixed base cost (land, permits, foundation),
and realistic random noise to simulate real-world variation (location,
finish quality, negotiation). This is a standard technique used in data
science teaching when a free live data source isn't available, and it
produces the same kind of linear relationship you'd find in a real listings
export. The script also intentionally introduces a few missing values and
duplicate rows, so the cleaning step in the ML pipeline has real work to do.

**Want to use a real live dataset instead?** See the "Using a real dataset"
section below — no code changes are required, only a CSV swap.

**What each column means:**

| Column       | Meaning                                              |
|--------------|-------------------------------------------------------|
| `SquareFeet` | The size of the house, in square feet                |
| `Price`      | The price of the house, in US dollars                |

- **Input feature:** `SquareFeet`
- **Target (what we predict):** `Price`

**Why Linear Regression is suitable:**
House size and house price have a well-established, approximately linear
relationship in real markets: each additional square foot adds roughly a
constant amount to the price (price-per-square-foot), plus some fixed base
cost and natural variation. With one numeric input and one numeric,
continuous output, and a roughly linear trend between them, Linear
Regression is the simplest model that correctly captures this relationship,
is fast to train, and — importantly for a teaching project — is easy to
interpret: the learned slope is literally "price added per extra square
foot."

### Using a real, live dataset instead

1. Obtain a CSV with real housing data (e.g. a Kaggle housing dataset, an
   MLS export, or a real-estate API response) containing a numeric size
   column and a numeric price column.
2. Replace `dataset/data.csv` with that file. If your column names differ
   from `SquareFeet`/`Price`, update the two constants at the top of
   `backend/data.py`:
   ```python
   FEATURE_COLUMN = "SquareFeet"
   TARGET_COLUMN = "Price"
   ```
3. Call `POST /train` again (or restart the server) — the dataset is
   re-loaded from disk fresh every time you train, so no other code changes
   are needed.

## 5. Machine Learning Methodology

Implemented in `backend/data.py` and `backend/model.py`:

1. **Data loading** — `pandas.read_csv()` reads `dataset/data.csv`.
2. **Data type checking** — feature/target columns are coerced to numeric;
   invalid values become `NaN`.
3. **Missing-value handling** — rows missing the feature or target are
   dropped (safer than imputing for a small linear-regression demo).
4. **Duplicate removal** — exact duplicate rows are dropped.
5. **Basic data analysis** — min/mean/max for both columns (returned by
   `GET /data`).
6. **Feature selection** — `SquareFeet` (X) and `Price` (y).
7. **Train/test split** — 80% train / 20% test, via
   `sklearn.model_selection.train_test_split` (fixed `random_state=42` for
   reproducible results).
8. **Training** — `sklearn.linear_model.LinearRegression().fit(X_train, y_train)`.
9. **Prediction** — `model.predict()` on new input.
10. **Evaluation**, computed on the held-out test set:
    - **R² Score** — how much of the variance in price is explained by size.
    - **MAE** — average absolute prediction error, in dollars.
    - **MSE** — average squared prediction error.
    - **RMSE** — square root of MSE, in the same units as price (dollars),
      making it easier to interpret than MSE.
11. **Model persistence** — the trained model is saved to
    `backend/trained_model.pkl` with `joblib.dump()`, and loaded with
    `joblib.load()` for predictions, so training only needs to happen once.

## 7. API Endpoints

Base URL (default): `http://127.0.0.1:8000`
Interactive docs (Swagger UI): `http://127.0.0.1:8000/docs`

| Method | Endpoint    | Description                                              |
|--------|-------------|-----------------------------------------------------------|
| GET    | `/`         | Health check — confirms the API is running.               |
| GET    | `/data`     | Returns basic dataset statistics.                          |
| POST   | `/train`    | Loads/cleans the latest dataset, trains and saves a model. |
| POST   | `/predict`  | Accepts `{"feature": <number>}`, returns `{"prediction": <number>}`. |

**Example — `POST /predict`:**

Request body:
```json
{ "feature": 1500 }
```

Response:
```json
{ "prediction": 237022.25 }
```

> Note: the model is trained automatically the first time the server starts
> (if no saved model exists yet), so `/predict` works immediately without
> requiring a manual call to `/train` first.

## 9. Installation (Windows / VS Code / PowerShell)

Open the project folder in VS Code, then open a PowerShell terminal
(`` Ctrl+` ``) and run:

### Step 1 — Create a virtual environment
```powershell
python -m venv venv
```

### Step 2 — Activate the virtual environment
```powershell
venv\Scripts\Activate.ps1
```
> If PowerShell blocks the script with an execution-policy error, run this
> once, then retry the activation command:
> ```powershell
> Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned
> ```

### Step 3 — Install dependencies
```powershell
pip install -r requirements.txt
```

### Step 4 — (Optional) regenerate the dataset
The repository already includes `dataset/data.csv`, so this step is
optional — run it only if you want a fresh sample:
```powershell
python dataset\generate_dataset.py
```

### Step 5 — Run the FastAPI server
```powershell
cd backend
uvicorn main:app --reload
```
You should see `Uvicorn running on http://127.0.0.1:8000`, and on first
launch the console will print that it auto-trained a model.

### Step 6 — Open the frontend
In a **new** File Explorer window (keep the server running), double-click:
```
frontend\index.html
```
This opens it directly in your default browser. The status pill in the
top-right of the page should turn green and say "API Online".

> If your browser blocks `fetch()` calls from a `file://` page, instead serve
> the frontend folder with a tiny local server (in a second PowerShell
> window, with the venv activated):
> ```powershell
> cd frontend
> python -m http.server 5500
> ```
> then open `http://127.0.0.1:5500` in your browser.

### Step 7 — Test the API directly (optional)
```powershell
curl http://127.0.0.1:8000/
curl http://127.0.0.1:8000/data
curl -Method Post http://127.0.0.1:8000/train
curl -Method Post http://127.0.0.1:8000/predict -Body '{"feature": 1500}' -ContentType "application/json"
```
Or simply open `http://127.0.0.1:8000/docs` in your browser for an
interactive Swagger UI to try every endpoint.

## 10. How to Use

1. Make sure the FastAPI server (Step 5 above) is running.
2. Open `frontend/index.html` in your browser.
3. In the **Make a Prediction** card, type a house size in square feet
   (e.g. `1500`) and click **Predict Price**.
4. The predicted price appears instantly in the result card — no page
   reload.
5. Check the **Model Performance** card for the model's R², MAE, MSE, and
   RMSE from its last training run. Click **Retrain Model** to retrain on
   the current dataset at any time.
6. Check the **Dataset Information** card for basic statistics about the
   data currently loaded on the backend.

## Working Flow (Plain-English Summary)

**Dataset → Training → Model → FastAPI → Frontend → Prediction**

1. `dataset/generate_dataset.py` creates `data.csv`, a documented dataset of
   house sizes and prices.
2. `backend/data.py` loads that CSV and cleans it (fixes types, drops
   missing/duplicate rows).
3. `backend/model.py` splits the clean data into train/test sets, trains a
   Linear Regression model on the training set, evaluates it on the test
   set, and saves it to `trained_model.pkl` with Joblib.
4. `backend/main.py` starts a FastAPI server that loads that saved model and
   exposes it over HTTP as `GET /`, `GET /data`, `POST /train`, and
   `POST /predict`.
5. `frontend/index.html` + `style.css` + `script.js` show a simple web page
   where a user types in a house size; `script.js` calls `POST /predict`
   with `fetch()` and displays the JSON response on the page instantly,
   without reloading.
